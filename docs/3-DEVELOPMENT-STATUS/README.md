# Development results — 24 October 2026

The mod is still a development prototype. These are the results of the latest continuation, not a claim that the complete seamless experience is ready.

| Feature | What was implemented | Actual outcome |
|---|---|---|
| Remember players across restarts | Persistent player identities and protected host credentials, with separate profiles per campaign | 26 checks passed in both PowerShell versions, including a real server restart. Human gameplay and a second PC were not tested. |
| One answer per conversation prompt | Each conversation has an ownership lease; each prompt has its own identity. Repeated clicks and old messages cannot create another accepted answer for that prompt. | **Passed with two real game clients.** The earlier host failure was a timing bug: the host asked to listen a moment before the guest's conversation existed and never asked again. It now retries, so it is registered in time to vote. Tested with bots, not a real story scene. |
| Main-story vote rules | Votes attach to the current prompt; the initiator wins a tie. Host status does not grant control over a guest's conversation. | Verified in server tests, including guest-owned tied votes. Actual story scenes and a finished voting interface are not connected yet. |
| Observe exact quest-related changes | An opt-in observer records operations from the game's FactsSet helper, including changes that occur between snapshots | **Passed its real game test.** Still limited to test facts and to the FactsSet helper; other ways quests change the world are not seen. |
| Guest changes reach the host | When the guest changes a fact inside a conversation or quest it controls, the change is written to the host's campaign record and applied on the host's game, keeping any time limit. The host does not record it again as its own change. | **Passed with two real game clients**: four changes, including two timed ones, arrived on the host exactly once. Test facts only, players were standing together, and a timed fact restarts its clock on the host. No real quest has been tried yet. |
| First real side quest shared | The second PC takes the real "Novigrad Hunt: Da'o" notice in Novigrad. The game records this with a direct engine write that the earlier watcher could not see, so a new watcher compares the whole list of game facts instead. The change goes to the host, and the host's own game then starts the same quest in its journal. | **Passed with two real game clients**, with the host about 590 m away. Only the start of this one quest is shared: the investigation, fight and reward, saving and loading, and every other quest are not done yet. |
| Progress survives loading a save | Loading a save used to switch the co-op layer off. Now, after any load, the game replays the shared campaign record onto the loaded world, so shared progress comes back even if the save is older. Conversations in progress are closed, and dialogue choices are never replayed. | **Passed with two real game clients**: the host received the Da'o quest from the second PC, then loaded a save from before it. Right after loading the quest was gone; the replay brought it back and the host's journal showed it again. Only tested with the host reloading the same save. |
| Quest progress from either PC reaches the other (party) | In a party, each PC sends the quest facts and quest-log updates it made since loading its save, and the other PC applies the ones that move it forward. The other PC's own quest graphs then react, so quests start and advance there too. Tutorial progress and load markers stay per player. Story choices, romances included, are shared. | **Passed with two real game clients** (`quest_share`): the second PC took three real notices; the host, which never touched a board, got all three facts and its own quest graphs activated the same two quests the second PC got; an advanced objective arrived in its quest log; a host change reached the second PC; nothing echoed back and forth. Limits: only what quests record in facts and the quest log travels (a scene or interaction step played on one PC does not run the other PC's quest graph); values only go up, removals are not shared; quest rewards granted by a graph reacting on both PCs were not checked; party mode only (the experimental campaign mode still uses its hand-approved list). |
| Nearby NPCs look the same on both PCs, and react to whoever is next to them | In a party, the host's game lists the townsfolk, guards and characters like Ciri around both players. Each one has a single owner whose game runs it: the host, unless the second PC walks up to it, so it reacts to the second PC's Geralt at once and without lag. The other PC never fights over its own copy: it hides it and shows a look-alike stand-in that only follows the owner. NPCs that already agree keep doing their own job, and extra townsfolk only on the second PC are hidden. | **Passed with two real game clients** (`npc_own`): the second PC walked up to Ciri, took her over, she followed its Geralt, and the host saw her follow; she went back to the host when it walked off. No running in place and no sliding feet on either screen, Ciri always shown exactly once, swaps landed within 1 cm, screens agreed within about 0.2 m while she walked. Moving stand-ins now play 0.15 s behind between timestamped updates (10 a second): stalled frames fell from 13 % to under 4 % (the same as real NPCs) and frame-to-frame jerkiness by about 40 %, though it is still above a real NPC's. Limits: only within about 45 m and in a party; at most 12 stand-ins; stand-ins only walk, run and stand: no work animations (the second PC's own copies cover most workers), gestures or chatter; stand-ins can't be talked to (walking up hands the real NPC over first); a quest character's own AI may still teleport her right after a hand-back (seen on both screens); tested at one street with Ciri. |
| Talk together (party) | When one player talks to an NPC, a party member within 40 m joins: its own game moves its Geralt beside the speaker and starts the same conversation with the same NPC, so it sees the camera, hears the voices and reads the subtitles. The player who started it chooses; the other player's clicks show up to them as suggestions ("name > choice"), and the chosen answer plays on both PCs. A shop or other menu the conversation opens stays with the player who asked. | **Passed with two real game clients** (`talk_share`): the second PC talked to the Novigrad general-store trader; the host 14 m away joined the same scene with the same 13 lines, its suggestion reached the second PC, both answers played on the host, the shop opened in the host's game was closed for it, and Farewell ended the conversation on both. Also fixed: the server dropped any fifth message channel per player (now 12). Limits: only conversations started with Talk; quest cutscenes that start by themselves are not shared yet; the joiner is moved beside the speaker; one merchant conversation tested; no cinematic quest dialogue or choice timer tested. |
| Travel together (party) | When a party member fast-travels, anyone in the party who stood within 60 m of them travels to the same signpost in their own game (own loading screen) and arrives beside them. Players who were elsewhere stay put, so the party can split up. A party member who was with you and changes region another way (quest, boat) is followed there. | **Passed with two real game clients** (`travel_together`): the second PC followed the host's fast travel across Novigrad and arrived beside it; after walking 150 m off it stayed put when the host travelled again. `travel_region`: the second PC followed the host's fast travel from Novigrad to Skellige. The region-change follow (quest or boat) is not tested yet. |
| Story scenes the quest starts by itself (party) | When a quest starts a scene on one PC (no Talk pressed), a party member within 60 m is brought beside that player, and its own game, kept at the same quest step by shared quest progress, starts the same scene there. It then watches and suggests like talk together. If its quest is not at that scene, it is put back where it stood after 10 s. If both PCs start the scene, the host chooses. Synced NPCs near any scene show as themselves for its duration. | **Passed with two real game clients** (`scene_share`), with a stand-in for the quest trigger (the bot starts the trader's scene when its Geralt comes within 6 m): the second PC was brought 20 m to the host, its own trigger started the same scene, the host's picks played on it, its suggestion reached the host, the trader was not a stand-in during the scene, and a scene its "quest" no longer had put it back 0.2 m from where it stood. Not yet tried with a real quest graph; joining is automatic, with no prompt yet. |
| Watch / Skip prompt | When a party member starts a conversation or quest scene near you, a popup asks whether to watch it. Watch joins it; Skip keeps you playing, and the outcome still reaches you through shared quest progress. A setting chooses Ask (default), Always or Never. | **Passed with two real game clients** (`watch_skip`): Skip kept the host out and in place; an unanswered prompt closed itself when the conversation ended; talk_share and scene_share pass with the Watch answer. The popup pauses the answering player's own game while open; the setting's labels are not localized yet. |
| Safer development launch | Build-hash checks, game-slot ownership, isolated profiles, child-only settings and cleanup if the owned server dies | Launcher fixture/network checks and a harmless process/lease test passed. Stable LAN release files remain unchanged. |

The server suite passed **255 unit assertions and 376 real UDP assertions**. The exact-operation journal passed **92 unit checks and 10 tests that deliberately broke its guards**. Native builds passed.

An initial game compile rejected scene-hook declaration syntax. Those unproven scene hooks were removed from active source. A later dialogue test failed because of the host listening race described above; after the fix it passes, and the older effects and sync tests still pass.

The server also briefly failed to save its campaign file when Windows had the file open in another program (for example an antivirus scan). It now retries the save for a moment instead of stopping.

The earlier successful bidirectional test remains useful evidence for the existing foundation; it does not prove this latest integration or a full quest.

Still to build: complete side quests while players are in different regions, all NPC/item/door/reward consequences, safe cinematic Listen, normal story voting controls, and shared progress that stays correct after every kind of save/load (only the host reloading has been tested).
